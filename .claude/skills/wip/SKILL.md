# wip — ブランチ作業メモ
ブランチ単位の「作業中メモ」を `.claude/artifacts/<branch>/wip.md` に保つ。セッションを切って
ブランチを切り替えても、次回ここを読めば作業を再開できる。**恒久的な事実は memory、
このブランチ限定・PR が出たら用済みの揮発メモが wip** と役割を分ける。
`.claude/artifacts/<branch>/` はブランチ単位の成果物ディレクトリ（gitignore 済み）。
wip メモのほか pr-description.md 等もここに同居する。
セッション開始時の自動読み込みは **SessionStart hook**（`wip-session-start.sh`）が担う。
この skill は **作成・更新・参照の手続き置き場**。
## 大原則（必ず守る）
- **1ブランチ1ファイル**：作業メモは `.claude/artifacts/<branch>/wip.md`
  （`feature/foo` → `.claude/artifacts/feature/foo/wip.md`）。
- **git に含めない**：`.claude/artifacts/` は gitignore 済み。**commit も push もしない**。履歴を汚さない。
- **ログではなくスナップショット**：このファイルは「今の状態」だけを表す。新しい状況は
  古い記述を **置き換える**。完了したアクション・古くなった要件は **消す**。
  append して育てない。再開時に読む量を常に一定に保つ。
- **初見の読み手に通じるよう自己完結で書く**：読むのは「この会話を見ていない別セッションの自分」。
  会話限定の符牒（「案B」「さっきの方式」「前述の通り」等）は禁止。方針を指すときは
  **その中身そのもの**を書く。略語・固有名は初出で1行説明する。
- **最重要は「課題」と「合意した方針の大枠」**：再開時にまず必要なのは
  「ユーザーが何を解決しようとしているか（なぜ）」と「どう解こうと合意したか（大枠）」。
  この2つをファイル冒頭に置き、ここだけ読めば文脈が復元できる状態にする。詳細要件はその次。
- **4本柱に絞る**：背景 / 解決したい課題、解決方針（合意した大枠）、作成物（現状）、残りのアクション。
  細かい要件・制約は「解決方針」の中に畳む。独立した「理由」節は作らない。
- **対象を絞る**：`develop` / `main` / `master` など作業の母体にはメモを作らない。
  feature/fix 等の作業ブランチのみ。
## 手順
1. **ブランチとパスを確定**：`git branch --show-current` → `.claude/artifacts/<branch>/wip.md`。
   母体ブランチ（develop 等）なら何もしない。
2. **既存あり**：読んで現状を1〜3行で要約し、「残りのアクション」の先頭から再開する。
3. **既存なし**：まず「解決したい課題」と「解決方針の大枠」を **ヒアリングして合意してから**、
   下記テンプレートで作成。ディレクトリは `mkdir -p` で用意。最初から埋まらない欄は空でよい。
4. **更新（私が自律的に実行）**：以下の節目で、該当セクションを **上書き** し末尾スタンプを更新する。
   毎回の許可は不要。ただしファイルの新規作成・大きな書き換えの方針は一言添える。
   - 着手直後（作成 or 既存への反映）
   - 課題理解・方針が確定 / 変更されたとき → 「背景 / 課題」「解決方針」を初見でも分かる言葉で書き直す
   - 作成物が進んだとき → 「作成物（現状）」を今の姿に書き換える
   - アクションを消化したとき → 完了分は消し、「残りのアクション」を更新する
   - セッションを閉じる前（`_exit` と併用してもよい）
5. **書いたら自己チェック**：「この会話を見ていない人がこれだけ読んで再開できるか」。
   符牒・指示語が残っていたら中身に展開する。
## テンプレート
```markdown
# <branch> WIP
## 背景 / 解決したい課題
<ユーザーがこのブランチで何を解決しようとしているか、なぜ着手したか。
 会話を見ていない初見の読み手に通じる言葉で。現状の不満・症状・きっかけを具体的に。
 ここはあまり変わらない>
## 解決方針（合意した大枠）
<どう解くと合意したか、その大枠と理由。「案B」等の符牒ではなく方針の中身を書く。
 採用しなかった案がある場合は「Xではなく Y（理由: Z）」と1行で。
 細かい要件・制約（命名・スコープ・対象範囲）もここに畳む>
## 作成物（現状）
<すでにできたもの・主要な変更箇所。進むごとに書き換える>
## 残りのアクション
- [ ] <次にやること。完了したら消すか done 化して、残りだけ残す>
---
_更新: <YYYY-MM-DD HH:MM> by Claude (<model>)_
```
## 注意
- **読み込みは hook、手続きはこの skill**。重複して常時 context を食わせない。
- PR をオープンしたらそのブランチのメモは用済み。残っていても害はない（gitignore 済み）が、
  気になれば `.claude/artifacts/<branch>/` ごと削除してよい。
